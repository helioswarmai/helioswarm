A swarm of autonomous
trading agents

Each agent has its own personality and its own wallet. All of them read one shared board before they act, so the swarm spreads out, gets out together and never trades against itself.

Presets / 6

Six personalities, stamped out as many times as you like

A preset is a set of traits scored from 0 to 255. Deploy one agent or thirty from the same preset, or bring named agents from the roster with their persona and rules intact.

The board / shared state

What the swarm does that a lone bot cannot

Every agent reads one board before it decides. The board shows what the others hold, what any of them just sold and every live signal about a coin.

  • It gets out together

    A whale sale or a large holder moving tokens sells every agent out of that coin at once, between ticks.

    exit

  • It never buys from itself

    After any agent sells a coin, no agent buys it for 30 seconds.

    30 s lock

  • It spreads out

    Cap how many agents hold one coin and how much SOL the whole swarm puts into it.

    caps

  • It reads the chain as it lands

    An optional gRPC stream turns every transaction on your targets into buys, sells and wallet moves, and can flag a large sell once it sits in a block and before it executes.

    stream

  • It does more than trade

    Groups also run price alerts with a webhook, and equity reports every 20 ticks. Add your own task with registerTask().

    3 tasks

Sequence / config to first tick

Three steps to a running swarm

  1. Write the groups

    One JSON file. Each group names its agents or a preset and a count, a bankroll per agent, the token mints it may trade and the tasks it runs.

  2. Start it on paper

    Prices come from Jupiter or an offline simulator. Fills, refused orders, alerts and reports land as JSON lines on screen and in a log file.

  3. Let it tick

    Every 15 seconds each agent applies your take profit, stop loss and time exit rules, then its brain decides to buy, sell or hold.

Live trading takes two switches. The config must say "mode": "live" and the environment must have SWARM_LIVE=1. With only one of them, the run stays on paper and says so.

Keys never go in the config. Every agent signs from its own keypair file, and its spend is capped by both its bankroll and what the wallet really holds.

Every order passes the same checks. Buy size, agent cash, per coin rules, the swarm spend ceiling and the order rate all apply to built in tasks and to your own.

No fake demand. Coordination is about risk. There is nothing here for staging buys across wallets or trading between the swarm's own wallets.

Run / paper mode

Run it in paper mode

You need Node and pnpm. No wallet, no RPC and no model key are required for a paper run.

Terminal
# get the code
git clone https://github.com/helioswarmai/helioswarm
cd helioswarm && pnpm install

# choose targets, groups and limits
cp swarm.example.json swarm.json

# a bounded paper run of 50 ticks
pnpm start -- --config swarm.json --ticks 50

The example config deploys two roster agents on BONK and WIF and three snipers on JUP. When the run ends it prints each agent's equity and profit or loss.

Questions / 7

Questions people ask first

Does it trade real money?

Not by default. Every run is a paper run unless the config says live and the environment has SWARM_LIVE=1. Live swaps go through Jupiter from each agent's own wallet.

Which tokens can it trade?

Any Solana token that Jupiter can price and swap. You list the mints each group may trade, and agents touch nothing else.

Do I need an AI model key?

No. The default brain reads the agent's traits and needs no model. An optional brain asks Claude with the agent's persona and falls back to traits if the call fails.

How do I stop it?

Press Ctrl C or create the kill file, named SWARM_STOP by default. The swarm stops and prints a final summary with each agent's equity and profit or loss.

Where do the keys live?

One keypair file per agent in a wallets folder beside your config. The folder is ignored by git, so back it up yourself. Deleting a file loses whatever that wallet holds.

Can the swarm be used to move a price?

It is not built for that. The board exists so agents spread out, exit together and avoid buying from each other. It has no way to stage buys to look like organic demand.

What are the limits today?

Books live in memory, so a restart starts every agent fresh while live positions stay in their wallets. Live fills are booked at the quoted amount. The decoders for sells seen before execution are untested against live traffic, so check them in watch mode first.
